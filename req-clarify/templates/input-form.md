## 一、必填项

| # | 项目 | 取值 | 说明 |
|---|---|---|---|
| 1 | **方案文档地址或路径** | ❓ 待填写 | 产品的方案原文。本地文件（`md` / `txt` / `doc` / `docx` / `pdf` 文本均可），或可公开访问的 `http(s)` URL。**需登录的链接（飞书 / Confluence / 内部系统）请先下载后填本地路径**。本 skill 会把原文与引用的原型/截图一并拷进迭代夹的 `原始资料/`，便于追溯 |
| 2 | **后端代码库路径** | ⚠️ 默认 `<当前终端目录>` · 待确认 | 后端仓库根目录（如 Java / Go / Python 服务）。**所有后端 `file:line` 证据相对它** —— 填错则整份问题单不可信 |
| 3 | **前端代码库路径** | ⚠️ 默认 `<当前终端目录>` · 待确认 | 前端仓库根目录（如 Vue / React 工程）。**所有前端 `file:line` 证据相对它**。与后端是**两个独立仓库**，各导一份基线 |
| 4 | **产物输出目录** | `<当前终端目录>/req-clarify-out/` | 迭代夹写在这里；实际产物落到 `<产物目录>/<方案名>/`（第 1 轮）或 `<产物目录>/<方案名>迭代<N>/`（第 N 轮，N≥2，后缀从 2 开始）。留空即用默认值 |
| 5 | **后端代码分支** | ⚠️ 默认 `master`（无则 `main`）· 待确认 | **只在哪个分支上取证**。开发常忘记切分支，工作区停在 feature 上时扫出的"现状"是开发中间态，澄清出的缺陷有一半是伪缺陷。留空即用默认；要用别的分支请显式写明 |
| 6 | **前端代码分支** | ⚠️ 默认 `master`（无则 `main`）· 待确认 | 同上，前端仓库的取证分支。前后端分支可不同 |

> **只有一端代码库时**：把另一端标「无」，该端跳过基线导出与扫描，产物头部写「前端：无（本次仅后端）」。

## 四、填写后的动作

填写确认后，本次运行按下列顺序执行，无需再回头确认输入：

```
输入表单确认

   ├─▶ 确定迭代夹：第 1 轮 `<产物目录>/<方案名>/`，第 N 轮（N≥2）`<产物目录>/<方案名>迭代<N>/`（后缀号 = 轮次号，从 2 开始，不存在「迭代1」）

   │        ├ prepare-baseline.sh 后端 → <基线根>/<后端repo名>/<分支>-<提交>（不在产物目录里）

   ├─▶ Stage 4 检查器+定级
   ├─▶ Stage 5 放行判定 ★分支

   │     └─ 无疑点 ─▶ 05-具体实现方案.md ─▶ AI/开发直接编码

```
