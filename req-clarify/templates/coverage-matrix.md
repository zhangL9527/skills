# 需求 × 现状 覆盖矩阵

**方案文档**：`路径` ｜ **后端代码库**：`路径@分支@提交` ｜ **前端代码库**：`路径@分支@提交`

> **填写规则**
> - 行 = 代码事实，列 = 需求条目。
> - **每格必须三态之一，不允许空格**：`✔` 已覆盖 / `✘` 明确不涉及（须写理由）/ `?` 未提及（须挂问题单编号）。
> - 空格 = 事实抽取漏了，回去补 Stage 1（G2 是硬门）。
> - 每个 `?` 在上报前**必须先过作用域判定**（见 `references/checkers.md`）。
>
> **与七维度扫描的关系**：矩阵管**深度**（每一类里的细节准不准），七维度扫描管**广度**（有没有整类功能被漏掉）。
> 矩阵里全是 `✔` 也不代表没问题 —— 可能是**那一整类根本没进矩阵**。两边都要做。

## 标记说明

| 标记 | 含义 |
|---|---|
| `✔` | 方案已覆盖且无歧义 |
| `✘` | 方案明确说不涉及（附理由） |
| `?` | 方案未提及 → **缺陷候选**，须挂 `Q-xxx` |
| `⚠` | 方案提及但属性不全（半填格）→ 须挂 `Q-xxx` |
| `⚔` | 两条及以上需求给出互斥值（冲突格）→ 须挂 `Q-xxx` |
