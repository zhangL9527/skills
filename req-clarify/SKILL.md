# 需求澄清：方案 × 代码库 → 问题清单 / 实现方案

**只产出 Markdown，不产出代码。** 输入：产品方案 + 代码库（前后端双仓）。输出二选一：

| 方案状态 | 产出 | 交给谁 | 接下来 |
|---|---|---|---|
| **有疑点** | **问题清单.md** —— 每条带 `file:line` 证据 | 产品 | 产品改方案 → 复用同一夹重跑 |
| **无疑点** | **实现方案.md** —— 变更点/DDL/验收标准俱全 | 开发 / AI | 直接编码 |

方案没问题就不出问题清单（硬造的是噪音）；问题清单是只读交付物，产品只通过改方案回应。

> 细则按需查：`references.md`（六类事实检索模式 · 七维度枚举法 · 实现方案写作硬标准）

## 产物目录（只有 3 个交付物）

```
<产物目录>/<方案名> 迭代/          # 单夹，每轮覆盖，不分轮次编号
├── 产品方案/                       # 方案原文，保留原始文件名
├── 问题清单.md                      # ★仅当有疑点
└── 实现方案.md                      # ★仅当无疑点（并删除上一轮遗留的问题清单.md）
```

- 产物目录默认 `<当前终端目录>/req-clarify-out/`；中间分析（事实/矩阵/检查器）全在对话内，不落盘。
- 代码基线快照落 `${TMPDIR:-/tmp}/req-clarify-baseline`，不进交付物、不进版本库。

## 输入（三项必填）

| # | 参数 | 说明 |
|---|---|---|
| ① | 项目地址（后端 + 前端仓库根） | 默认当前终端目录，**必须经使用者确认才生效**；前端可标「无」跳过 |
| ② | 方案文档（本地文件或 URL） | md/doc/docx/txt/pdf 文本 |
| ③ | 取证分支（后端 + 前端） | 默认 `master`（无则 `main`），两端分别算 |

缺参数就逐项问（`AskUserQuestion`）；**已经给过的值一律不再问一遍**。仓库要校验：路径存在、可读、是 git 仓库根、有源码。不合格只重问该项并说清实测结果，**不许对着空目录编清单**。

## 代码基线（证据可信的根基）

开发常忘记切分支 —— 工作区停在 feature 分支时，扫出的"现状"是中间态，一半"缺陷"是伪缺陷。双仓各跑一次：

```bash
bash <skill目录>/scripts/prepare-baseline.sh <repo路径> [基线根目录] --branch <分支> --label 后端
```

- 导**只读副本**，不切使用者工作区、不碰未提交改动；同一 `(repo,分支,提交)` 内容寻址自动复用。
- 脚本自行处理三种情形（分支完整 / 有未跟踪源文件需补入 / 分支不存在退回工作区），**降级必须告知使用者**。
- **从这一刻起，所有代码读取都指向基线目录，不指向工作区**；`file:line` 一律相对基线目录。
- 分支与提交写进 `实现方案.md` 头部两行；`问题清单.md` 是给产品看的，不放取证信息。

## 核心模型：差集即缺陷

```
缺陷集 = 代码事实空间 − 方案意图空间
```

- **深度（覆盖矩阵）**：行=代码事实、列=需求条目，每格三态 —— `✔` 已覆盖 / `✘` 明确不涉及 / `?` 未提及。每个 `?` 是一条**方案疑点**候选（方案写了但没说全/前后矛盾/与代码对不上）。矩阵在对话内构建，不落盘。
- **广度（七维度扫描）**：新增物（类型/入口/字段/状态/规则/角色/渠道/配置）给系统加了**新的分流维度**，凡是按它分流或被它影响的存量功能都要表态 —— ①数据可见性 ②行为分流 ③字段与校验 ④副作用 ⑤流程与时效 ⑥对外与集成 ⑦权限与配置。波及但方案没提 = **方案遗漏**；确定不受影响 = 对话内留痕，不进交付物。同一根因合并成一项。
- **代码事实六类**（要全集不要抽样，每条带 `file:line`）：入口 / 类型 / 字段 / 流程 / 约束 / 副作用。沿调用链抽、抽"行为"不抽"名字"；走到共享查询/写入入口时停下横向展开（遗漏高发区）。
- 面向产品的产物里叫「方案疑点 / 方案遗漏」，维度标注列叫「**影响维度**」，不暴露"深度/广度"。

## 执行流程

**Stage 0 · 输入解析 + 双基线锁定**：校验输入 → 读方案总结方案名（≤12 字，去非法字符）→ 建夹 `<产物目录>/<方案名> 迭代/`（已存在则本轮覆盖）→ 方案原文 `cp` 进 `产品方案/`（保留原始文件名；需登录抓不到的不落盘，提示用户自行下载）→ 跑 `prepare-baseline.sh` 锁双端基线 → 拆成可编号的需求条目（`REQ-xxx`）→ 圈定作用域（范围外的代码事实不上报）→ 判定新增物种类（决定七维度重点）。

**Stage 1 · 代码事实抽取**：按六类抽全集，每条带 `file:line`，按端分节（各类抽法与检索模式见 `references.md` 第一节）。

**Stage 2 · 七维度扫描**：逐维度问「新增的这批数据要不要影响它」→ 方案遗漏候选（各维度枚举法与扫描方式见 `references.md` 第二节）。

**Stage 3 · 覆盖矩阵**：见核心模型。四类检查器过一遍：**C1 覆盖**（矩阵里的每个 `?`）· **C2 一致**（方案描述与代码行为矛盾；同一概念多个叫法也算）· **C3 完备**（方案给了对象但缺字段/枚举/边界值）· **C4 流程等价**（新流程与现有等价流程的节点/时序差）→ 疑点定级（高=不澄清必然做错 / 中=大概率做错 / 低=理解成本）。

**Stage 4 · 提问价值自检（路径 A 专属）**：覆盖矩阵与七维度保证「不漏」，不保证「每条都值得问」—— 凑数问题会让产品对整份文档的可信度打折。每条候选过四道闸门：

| 闸门 | 判据 | 不过关的处置 |
|---|---|---|
| ① 产品拍得了吗 | 答完方案里会多出一句**业务规则**吗（排序/表名/命名/框架不算） | 降级为「给开发」备注 |
| ② 答案会改变方案写法吗 | 建议默认 = 维持现状/不需要/照搬存量 → 零信息量 | 降级为备注，并把下面的真问题捞出来改写 |
| ③ 能被另一条推导吗 | 依赖型、同主题 | 合并，不新增编号 |
| ④ 方案原文能读出来吗 | 已写明或读完即得 | 降级为背景事实 |

★ **方案改写句测试**：「产品答完这句，方案里要改成哪一句？」改不出来 → 丢弃（对话内留痕：一句理由 + `file:line`）。清单 **≤15 条**；超了先合并同主题、再砍低级别。

**Stage 5 · 分支判定**：自检后疑点非空 → 路径 A；空 → 路径 B。

**路径 A · 产出问题清单**：按 `templates/issue-list.md` 产出（双层结构：上层「给产品一句话」，下层「给开发」带证据/选项/建议默认；分「方案疑点」「方案遗漏」两部分）。夹内已有旧版 → 先读，逐条对比沿革（已答/未答/新增/剔除）给使用者一段说明，然后覆盖。交付前逐条核对 `file:line` 指向的那一行**语义对得上**（行号有效但指向相邻字段，只有人眼能查）。暂停并交付，**不产出实现方案.md**。

**重跑**：产品提交新方案 → 复用同一夹 → Stage 0 起全重跑（一次改稿常连带影响别处），循环直到疑点清零 —— 高/中级必须清零；低级可带默认建议进路径 B，但要在实现方案的「不做清单」或「边界与异常」里写明。

**路径 B · 产出实现方案**：删除上一轮遗留的 `问题清单.md`，按 `templates/implementation-plan.md` 产出，写作硬标准见 `references.md` 第三节 —— **AI 照着它写代码，不需要再问任何问题**：文件 + `file:line` + 锚点方法 + 可照抄的改法、类名方法、DDL、接口契约、流程步骤与失败处理、不做清单、术语表、逐条验收标准、存量功能结论落地对照（每条方案遗漏与每条「无需调整」都要有落点）。仍不产出代码。

## 红线

1. 代码库路径必须使用者确认；默认值未经确认不生效，确认时回显两端最终路径。
2. 已给过的输入不再问一遍。
3. 所有代码读取指向基线目录；降级情形必须告知使用者。
4. 作用域外的代码事实不上报。
5. 不问产品拍不了的技术细节；不问答案早已确定的问题（建议默认=维持现状/照搬存量）。
6. 同一主题最多一条；依赖型问题不单独问；每条问题必须能改写成方案里的一句话。
7. 没有代码证据的问题不要提；不替产品做决策（只列可选解读+建议默认）。
8. 丢弃一条疑点 ≠ 抹掉 —— 对话内留痕（理由 + `file:line`）。
9. 方案无疑点就不出问题清单；两份交付物二选一，出实现方案时删除旧问题清单。
10. 交付物只留问题本身 —— 排查范围/版本记录/基线信息/方案路径一律不写进交付物。
11. 不产出代码 —— 终点是 Markdown。

## 运行方式

```
/req-clarify                                              # 无参数 → 逐项问输入
/req-clarify <方案地址> --repo-backend <路径> --repo-frontend <路径> \
             [--branch <分支> | --branch-backend <分支> --branch-frontend <分支>] [--out <目录>]
```

带参数时跳过提问，参数直接作初值（`--repo-*` 视为使用者已确认），只问参数没覆盖到的项。
