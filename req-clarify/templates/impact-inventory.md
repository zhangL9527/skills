# 七维度扫描底稿

> **Stage 2 的工作稿，落到 `02b-七维度扫描底稿.md`。** 目的是保证**广度** —— 不漏掉"新增这个之后，存量里还有哪些功能会被牵连"。
> 扫完的结论最终并入 `03-澄清问题单.md`：
> - 「需澄清」的行 → 写成一条**方案遗漏**（进「第二部分 · 方案遗漏」）
> - 「无需调整」的行 → 计入问题单**「排查范围」表**的「确认不受影响」列
>
> **产品不需要填这张表，它也不发给产品。** 它是扫描留痕，不是问卷 —— 交付物里只出现它的汇总。
> 但**必须落盘**：它是 G1b 的证据底座（每条结论都要有 `file:line`），也是每轮重扫时对比「结论变迁」的依据。

**重点维度**：`<填>`（见 references/impact-inventory.md 的映射表）
**后端代码库**：`路径@分支@提交` ｜ **前端代码库**：`路径@分支@提交` ｜ **作用域**：`模块A / 页面B / 接口C`

## 填写规则

| 列 | 填什么 |
|---|---|
| **#** | 维度.序号（1.1 / 2.3 …），供问题单和实现方案追溯引用 |
| **存量功能** | 代码里真实存在、**可能被本次新增牵连**的功能。合并同根因（5 个按钮共用一个查询 = 1 行） |
| **现状行为** | 代码现在怎么做的 —— 一句话，带证据 |
| **代码位置** | `file:line`。**没证据的不列** |
| **结论** | `需澄清` / `无需调整` |
| **理由 / 转为问题** | `需澄清` → 写清疑点要点与将生成的 `Q-xxx`；`无需调整` → 写一句为什么不受影响 |

> **「无需调整」也要写一句理由。** 它是免责证据，也是让读者知道"这里查过了"的凭据。
